# Expandable visual recipes

The hybrid planner loads `*.json` here on every new plan. A file change changes
the library fingerprint and invalidates prior source-bound choices. There is no
fixed twenty-concept ceiling: installed reviewed object assets combine with seven
registered compositions, alongside narrative concepts and physical actions.

Use `source_recipes.json` as the data format example. Only reviewed nonhuman icons,
literal source phrases, a registered motion and an English visual goal are allowed.
Code, paths, unknown assets, duplicate IDs and extra fields are rejected. Human
recipes require a registered Blender implementation; JSON cannot add human code.

This expands source matching and composition choices, not arbitrary animation
capability. Adding a new renderer or asset requires engineering and validation.
Recipes are symbolic illustrations; they must not introduce factual claims.

Each nonempty plain-text line owns one visual. Each SRT cue owns one visual,
including cues whose text wraps onto several display lines. Long lines remain
one shot; split them in the input when a separate visual is intended. Original
source and voice files remain unchanged. No source captions are burned in.

The host assigns real camera variations when subject content recurs. Fifteen
registered camera profiles exist per identical content combination; exhausted
alternatives stop with a line number rather than recycle or relabel a shot.
Characters and objects can recur for continuity. Identical complete shots cannot.

Plan signatures ignore scene IDs. A decoded five-frame comparison at normalized
shot positions also blocks identical or very close rendered sequences before
publication. It is a heuristic, not a guarantee against all semantic repetition
or a certification of artistic quality. Previous deliveries survive failed checks.
